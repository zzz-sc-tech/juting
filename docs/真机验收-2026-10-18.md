# 真机验收记录（Android Chrome）

> 时间：2026-10-18 ｜ 设备：Android 模拟器 Pixel_API_34（Android 10 内核 / **Chrome 113**）
> 视口：393×701 CSS px，DPR 2.75 ｜ 服务：`vite preview --host 0.0.0.0 --port 8105`
> 连接方式：`adb forward tcp:9222 localabstract:chrome_devtools_remote` + Playwright `connectOverCDP`
> 说明：这是**真实 Chrome for Android 渲染引擎**，不是 Chromium 的 `isMobile` 模拟。

---

## 0. 为什么真机与模拟器结论不同

| 维度 | Chromium 模拟（`isMobile: true`） | 真机 Android Chrome |
|---|---|---|
| 视口高度 | 844（等于窗口） | **701**（Chrome 地址栏 + 状态栏吃掉 143px） |
| `100vh` | = 844，等于可见高度 | **757**，比可见高度多 56px（地址栏区域） |
| `pointer` 媒体查询 | `coarse`（因为 hasTouch） | **`fine`**（模拟器接了鼠标）→ 所有 `@media (pointer: coarse)` 规则不生效 |
| 横屏高度 | 390 | **268** |
| 渲染引擎 | Chromium | Chrome for Android（同为 Blink，但视口/UA/输入模型不同） |

结论：**模拟器能验布局，验不了视口与输入模型**。下面 5 个问题都是模拟器测不出来的。

## 1. 真机发现并已修复的问题

### ① 词典侧栏整体跑到屏幕外，底部「收藏」不可达（最严重）

- **现象**：点句中任意一个词，侧栏从 y=439 开始、底部到 1140（视口只有 701），「收藏」按钮在 y=1131 —— 完全在屏幕外，**手机上根本没法收藏生词**。
- **根因**：`stage-enter` 入场动画用了 `animation-fill-mode: both`，终态是 `transform: translateX(0)`。任何非 `none` 的 transform 都会给 `position: fixed` 的后代**新建包含块**，侧栏于是相对 `.stage-viewport`（y=439）定位，而不是视口。
- **修法**：`fill-mode` 改 `backwards`（动画结束后回落到元素自身的 `transform: none`）。
  注意：把终态写成 `transform: none` 不够——Chrome 会把它解析成 identity matrix，仍然创建包含块。
- **复测**：`top 0 / bottom 701`，footer `636–701`，在可见区内。

### ② 侧栏高度用 `100vh`，底部 56px 被浏览器 UI 压住

- **修法**：`height: 100dvh`（保留 `100vh` 作为不支持 dvh 的兜底）。

### ③ 关闭按钮 26×26，且 `pointer: coarse` 在这台机器上是 `fine`

- **现象**：真机上 `matchMedia('(pointer: coarse)')` 返回 **false**（模拟器挂了鼠标），我上一批写的 44px 触控目标**全部没生效**。
- **修法**：媒体查询改成 `@media (pointer: coarse), (max-width: 720px)` —— 用宽度兜底，不依赖指针类型。关闭按钮补 `min-height/min-width: 44px`。
- **复测**：`44×44`。

### ④ 横屏可视高度只有 268px，正文只剩 13px

- **现象**：`844×390` 的模拟结论（正文可见 119px）在真机上不成立，真实横屏 innerH 只有 **268**：顶栏 64 + 横幅 61 + 阶段栏 46 → 媒体区只剩 13px。
- **修法**：横屏块里隐藏品牌副标题、顶栏 `min-height: 48px`；新增 `@media (max-height: 320px) and (orientation: landscape)` 整块隐藏章节横幅。
- **复测**：顶栏 48、横幅 0、媒体顶部 169 → **可见 99px**。

### ⑤ 弯撇号把 don’t 拆成 don + t，点词查到错误释义

- **现象**：真机上点词弹出的词头是 **"t"**（词典给了「表/终端/测试」这种缩写释义）。
- **根因**：`splitClickableWords` 的 `WORD_RE` 只认 ASCII 撇号 `'`，转写稿里大量是 Word 自动替换的弯撇号 `’`，于是 `don’t` 被切成 `don` + `t`。
- **修法**：`/[A-Za-z][A-Za-z'’-]*/g`；补一条单测。
- **影响面**：所有含 `’` 的转写句（n’t / ’s / ’ll 等）都受影响。

### ⑥ 吸顶题号导航切题后盖住题干

- **现象**：滚动后点题号切题，卡片顶部 89px 被吸顶导航压住（截图里「第 1 题」和状态徽标被切一半）。
- **修法**：`goToQuestion()` 在卡片顶被压到导航下方时 `scrollIntoView`，配合 `scroll-margin-top: 72px`。
- **复测**：切题后卡片顶与导航底间距 **+2px**（不再遮挡）。

## 3. 仍然没验的

- **iOS Safari**：没有设备。iOS 的 `position: sticky` 在滚动容器内、`env(safe-area-inset-*)`、软键盘弹出行为与 Android 不同，仍需真 iPhone。
- **Chrome 中文页面自动翻译提示**：模拟器系统语言是 en-US，打开 `lang="zh-CN"` 的页面会弹「翻译成英文」条。产品是纯中文，可考虑加 `<meta name="google" content="notranslate">`，但会同时挡掉用户主动翻译，需你决定。
- **弱网/低端机**：模拟器性能不代表真机。

## 4. 复现方式

```bash
# 1) 起局域网预览（8101 只绑 127.0.0.1，手机访问不到）
cd web-app && npx vite preview --host 0.0.0.0 --port 8105

# 2) 起模拟器
%LOCALAPPDATA%\Android\Sdk\emulator\emulator.exe -avd Pixel_API_34 -gpu swiftshader_indirect

# 3) 连调试
adb forward tcp:9222 localabstract:chrome_devtools_remote
# 模拟器内访问 http://10.0.2.2:8105/home

# 4) 跑验收
node temp/review/device-accept3.mjs      # 侧栏 + 吸顶
node temp/review/device-word.mjs         # 点词行为
```
